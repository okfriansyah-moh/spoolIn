# Compose network and loopback port correction

Source base: `1a0e83026a0e2fe3cd4f967178f86cdf13c0de52`. This correction follows the failed [remote run 39090751636](https://github.com/okfriansyah-moh/spoolIn/actions/runs/39090751636). Its inspected `runtime/readiness-probes.json` reports all eight containers running, but Core/Catalog/Media/Grafana HTTPS probes return curl exit 7 and HTTP 000. Container state is not application readiness. This source change is a diagnosis-led correction; causal resolution and acceptance require the next actual remote run.

Approved TD §2.2 (`docs/04-spoolin-techdoc.md:170`) specifies five configurable loopback operator/application ports while keeping PostgreSQL 5432, per-container gRPC 9090, restricted Actuator 8081 and MCP exporter 8788 on the private Compose network. TD line 132 describes loopback host entry points and private backend/scrape endpoints. It does not select a blanket outbound-network prohibition for the application; selected fixed notification adapters require outbound access under their existing endpoint controls.

[Docker's bridge documentation](https://docs.docker.com/engine/network/drivers/bridge/) describes user-defined network isolation, DNS, NAT egress and published host addresses. The [Compose network reference](https://docs.docker.com/reference/compose-file/networks/) distinguishes internal network isolation from ordinary application-private network membership. [Moby issue 44986](https://github.com/moby/moby/issues/44986) records host publication failure for services attached only to an internal network. That report supports the diagnosis but does not prove the cause of this application's failed run without a corrected rerun.

The private network now explicitly uses the user-defined bridge driver with default host-binding address 127.0.0.1. Every actual published binding also explicitly specifies 127.0.0.1. No host networking, privileged container, public binding, database/gRPC/exporter publication or certificate bypass is introduced. Existing mTLS, API authorization, Grafana authentication, fixed outbound adapter rules, resource limits and container restrictions remain effective.

| Entry point | Configuration | Default host port | Container port |
| --- | --- | --- | --- |
| Core browser HTTPS | CORE_HTTPS_PORT |8443|8443|
| Authenticated MCP | MCP_HTTP_PORT |8787|8787|
| Prometheus operator | PROMETHEUS_HTTP_PORT |9090|9090|
| Alertmanager operator | ALERTMANAGER_HTTP_PORT |9093|9093|
| Authenticated Grafana HTTPS | GRAFANA_HTTPS_PORT |3000|3000|

Prometheus and Alertmanager now have their documented loopback bindings. The three previously published management ports 18443/18444/18445 are removed. Owner readiness executes the bundled `private-readiness.mjs` inside the existing pinned MCP container, reaching only `https://core|catalog|media:8081/actuator/health/readiness`. It uses the MCP service certificate/key and configured CA; owners already authorize the MCP identity for private health while denying it scrape access. Host and certificate validation remain enabled, requests have a two-second total deadline and 64 KiB body cap, and output contains only allowlisted status/components and fixed failure reasons. Grafana health retains trusted HTTPS from the host. All eight container observations and actual owner database/seed/work status observations remain in `readiness.py`; private health is not replaced with container existence.

`ports.py` runs before the image build, validating the fully resolved Compose contract, all five port ranges and uniqueness, current host socket availability, and actual Docker project/service/target ownership. An exact running binding belonging to this installation permits repeat startup. Foreign, mismatched or duplicate occupiers are refused; stopped container metadata is not treated as an active listener. The check neither stops unrelated services nor changes their ports. Docker's final allocation remains authoritative because another process can occupy a port after preflight.

After services start, `ports.py --verify` inspects actual running container publications and the actual network driver/internal setting. It rejects missing operator bindings, wildcard/IPv6 publications or any backend/exporter host binding in this installation. The safe revision/run-bound report is `.ai/reports/network-bindings.json`, configurable through SPOOLIN_NETWORK_REPORT. This is an actual network assertion when executed, separate from the following trusted application-readiness checks and browser acceptance. Existing installations using an old internal network require deliberate owned-network recreation while preserving volumes; this source change does not silently remove a live network.

Remote regression entry points are `python3 ops/ci/ports-test.py`, `python3 ops/ci/readiness-helper-test.py` and `node --test ops/ci/private-readiness-test.mjs`. Component fixtures prove contract handling/redaction, not network reachability or application readiness. The real make-start run must inspect the actual bindings report, successful private mTLS owner readiness, trusted Grafana/Core access and subsequent browser assertions. Restore and parallel namespaces must provide distinct configured host ports, including the two new operator settings.
