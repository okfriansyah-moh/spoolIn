# Operator command proof boundaries

The hosted `ops/ci/verify-operator-commands.py` stage uses the original uniquely owned `ci-<run>-<attempt>` installation after normal browser, monitoring, Make, rotation and backup/restore checks. It requires GitHub-hosted Linux and refuses another namespace or Compose-skip mode. All commands, containers and tests run remotely. This source addition is not an execution receipt or acceptance closure.

Connector/protocol checks occur while the application is running. The stage then pauses MCP/Core/Catalog/Media through the actual Compose installation before controlled operational fixtures. PostgreSQL remains running. These tests intentionally retain unresolved work and histories, so owners stay stopped through evidence collection and teardown; no synthetic notification is sent to an external provider. Later healthy-stack claims cannot reuse this final state. This is operational fault injection under ATDD-158/200/208, not proof that a browser action or provider request succeeded.

| Command | Actual remote checks | Proof limits |
| --- | --- | --- |

An independently held installation lock forces the actual120s timeout/exit4 and remains owned by its holder. | Empty/previous-version migration, transactional DDL rollback and killed nontransactional index cases still require their separate assigned evidence. | `recover-work.sh` | Protected local operator authority; invalid authority-directory mode and missing reason refused; inspected original ID/generation/epoch/history; stale generation and epoch refused. Actual packaged CLI recovers proven failed-before-acceptance notification into one bounded generation, preserves epoch/effect/original receipt and prior phases, writes one recovery event and rejects stale replay. UNKNOWN delivery is refused without changing work/history. | No external provider acceptance or actual user-host compatibility. Failed notification evidence is controlled SQL setup; no arbitrary unknown effect is made eligible. Media/domain destination reconciliation remains separately assigned. |
| `maintenance.sh` | Inspect validates actual protected maintenance connection without effects; hourly101 expired REQUEST bodies require two bounded passes, preserving receipt identities and typed initialization rows. Daily purge deletes eligible paired terminal work/history while retaining EXHAUSTED, UNCERTAIN and unmatched phase evidence for each owner. Before/after row counts and sorted row digests preserve Core key metadata, Catalog audit/provenance/seed/proposal ledgers and Media assets/references/hold bindings. Actual maintenance credentials cannot perform DDL or delete lifetime receipts. Unknown arguments exit2. | Separate draft-save/purge races, proposal redaction, Media processing-block/output/holds and other full retention obligations remain pending their actual assigned checks. These cases do not certify all ATDD-208. |
| `status.sh` / `make status` | Actual degraded script exit1 and Make exit2; inspect returned owner-state probes for retained EXHAUSTED work in all owners. | Writers are deliberately stopped too; report both causes. This is not a healthy-readiness claim. |
| `tunnel.sh` | Existing unsupported-runner refusals stay pending with exit78. | Missing registration/capability remains an external obligation and does not skip independent operator checks. |

Fixture SQL uses only synthetic IDs, ordinary owner records and explicit historical timestamps. Runtime/maintenance/backup passwords are read inside the private PostgreSQL container from protected files; they are never printed, placed in URLs or arguments, or included in evidence. The production JVM CLIs run through the actual packaged Compose services with their configured verified-TLS database settings; no host Gradle runner or private DNS workaround is used. Controlled SQL socket access is setup/observation, distinct from the production CLI connection boundary.

The JSON report records tested SHA, workflow run/attempt, runner OS/image, phase results, actual script exits/durations and hashes of withheld command output. It is rewritten after each completed phase, preserving failed conclusions while later independent checks continue. Exit1 dominates failed assertions; exit78 preserves the pending tunnel when executable checks succeed. Empty selections never pass. No raw process exception, secret-bearing stdout/stderr, environment file or database payload is retained. Original request tombstones and unresolved work/history remain in this disposable installation until teardown.

Required remote entry points: `python3 ops/ci/operator-runtime-test.py` for orchestration regressions and `python3 ops/ci/verify-operator-commands.py` for actual operator/database assertions. Component tests patch subprocess calls only to check orchestration/error aggregation; they cannot satisfy the runtime cases. The coordinator adds real run/job/artifact links after dispatch and inspection and retains previous failures. No review ceremony or acceptance operation is performed by these helpers.
