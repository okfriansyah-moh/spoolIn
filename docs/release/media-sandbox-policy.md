# Media codec container policy

Remote run 39097374811 assessed `fadcf404c1a763be68b9b2cc84a251b062eafa00`. Its real UID/GID 10001 Media image had Bubblewrap 0.11.2, read-only root, no-new-privileges, zero effective/bounding capabilities, Seccomp 2 and docker-default AppArmor. Header setup failed at namespace creation. This is retained failed production evidence; the successful host prerequisite is a separate boundary.

Docker 28.0.4's [default seccomp source](https://github.com/moby/moby/blob/v28.0.4/profiles/seccomp/default.json) excludes namespace-bearing clone and unshare without CAP_SYS_ADMIN; its [AppArmor template](https://github.com/moby/moby/blob/v28.0.4/profiles/apparmor/template.go) denies mounts. These restrictions conflict with the required unprivileged Bubblewrap setup. The generic failure message alone does not establish which control rejected the first syscall.

`ops/security/media-seccomp.json` retains the entire pinned Docker default, including default errno-deny, all original argument filters, clone3 fallback and capability conditions. `media-sandbox-policy.json` records the upstream byte hash, structural hash and four added rules. The additions permit only two exact clone argument values used by `--unshare-all` (with or without cgroup namespaces), the exact second-user-namespace unshare flag, and mount/umount2/pivot_root. setns, arbitrary namespace flag combinations and unrelated administrative syscalls remain denied. Mount syscalls still require kernel permissions in the owning user namespace; the container receives no added capabilities.

The Media-only enforcing AppArmor profile retains the Docker proc/sys restrictions. It permits setup at fixed private-root, library/input/output/device mount paths. It does not grant a broad mount rule. Under no-new-privileges a later transition cannot grant missing setup authority, so the outer Media profile necessarily carries these constrained setup permissions. The fixed `/usr/bin/prlimit` launch stacks `spoolin-media-codec`, which denies network, capability, mount, umount, pivot_root, further user namespaces and ptrace, and restricts writes to temporary data and the selected output files. The fixed production codec command still creates separate namespaces, a read-only root, private mounts, no network, and CPU/memory/file/time limits. See the [AppArmor policy syntax and stacking rules](https://manpages.ubuntu.com/manpages/noble/man5/apparmor.d.5.html).


Run 39102353927 at `2d3db725d8f3d445ccfa0537015eae601fc21405` subsequently reached the actual restricted container: status and namespace collection succeeded with UID/GID 10001, zero effective/bounding capabilities, no-new-privileges, Seccomp 2 and `spoolin-media`. The pipeline exited 126 at the version stage after vips/Bubblewrap output and before prlimit output; its bounded kernel observations recorded an exec denial. No header/encode namespace proof was established in that run.

The fixed prlimit rule now names `spoolin-media//&spoolin-media-codec` directly using `px`, with no inheritance or unconfined fallback. In the pinned [Linux 6.17 AppArmor transition implementation](https://github.com/torvalds/linux/blob/v6.17/security/apparmor/domain.c#L517-L656), a leading `&target` first resolves that stack, then searches for a separate executable attachment before merging. prlimit has no such attachment, so the old rule failed. An explicit complete compound label instead resolves the two named profiles directly and retains the original Media restriction under no-new-privileges. Missing targets fail lookup and execution; the prerequisite check also rejects a missing codec profile. The source regression covers that failed prerequisite and exact no-fallback rule; actual kernel negative enforcement and corrected production codec execution remain remote proof obligations.

On the intended Linux Docker host, provision this exact reviewed policy before `make start`:

```sh
sudo bash ops/bin/provision-media-sandbox.sh --install
sudo bash ops/bin/provision-media-sandbox.sh --check
```

The installer requires root, a protected nonblocking operator lock, regular root-owned files and protected directories. It refuses a different installed revision, symlinks or an already loaded partial/non-enforcing selection. It adds only `spoolin-media` and `spoolin-media-codec`; it never replaces docker-default, changes sysctls, adds container capabilities, disables seccomp/AppArmor, or makes the container privileged. Compose references the protected seccomp copy at `/etc/spoolin/security/media-seccomp.json`. Missing host profiles prevent container creation. Unsupported hosts retain a prerequisite failure rather than silently running without enforcement. Policy revision replacement requires an explicit operator migration after stopping owned Media containers; this installer does not overwrite a loaded revision.

Inspect all header/encode stages and namespace IDs. Also retain negative observations for original-namespace mount, decoder network/capability/userns denial and writes outside the output/temp paths. Source policy checks and successful profile provisioning do not establish codec runtime acceptance. No local container, parser, build or test execution was used to prepare this change.
